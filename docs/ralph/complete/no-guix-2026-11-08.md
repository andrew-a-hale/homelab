# Ralph: Guix removed, pacman only (2026-11-08)

**Date:** 2026-11-08
**Status:** done, verified — `/gnu` gone, 200MB returned, every service still up.
**Ticket:** none — follow-up to
[`arch-install-2026-11-07.md`](arch-install-2026-11-07.md).

Guix was installed as a foreign distro on 2026-11-07 with the intent that it
would own packages ("declarative, rollback-able, per-user generations"). One day
later it owned nothing, so it came off.

## Decision and why

**Remove Guix rather than grow into it.** Measured on the live box before
removal:

| What Guix was costing | |
|---|---|
| `/gnu` | 1.0 GB, 608 store entries |
| `/var/guix` | 9.5 MB |
| `guix-daemon` | resident, **60 MB RSS**, always on |
| `/gnu/store` read-only bind mount | one more moving part at boot |

| What it was delivering | |
|---|---|
| `andy` profile | `nss-certs` only — Arch already has `ca-certificates` |
| root profile | empty |
| packages actually running from `/gnu/store` | none |
| Arch packages available in Guix | `git`, `go`, `rsync`, `vim`, `wget`, `nginx`, `fail2ban`, `qbittorrent`, `btrfs-progs`, `exfatprogs`, `gptfdisk`, `ntfs-3g`, `tpm2-*`, `cryptsetup`, `iwd`, `udisks` |

Every movable candidate was **older than what pacman already had** (Guix pin
`230aa37`: git 2.52 vs 2.56, go 1.22 vs 1.27, vim 9.1 vs 9.2), and everything
Guix was *newer* at is substrate it must never own: kernel, firmware,
cryptsetup, TPM2 tools, sshd, sudo, iwd, udisks2, nfs/ntfs mount helpers — all
need PAM, setuid, D-Bus, systemd units or to exist in the initramfs before Guix
does. Missing from Guix entirely: `cloudflared`, `tailscale`, `ufw`, Jellyfin,
Proton VPN's official CLI/daemon.

So the trade was: two package managers, a daemon, a read-only mount, 1 GB, and
a version lag — in exchange for nothing. A second package manager on a box that
runs nothing from it is a debugging surface, not a feature. If a tool ever
appears that Arch lacks, `guix-install.sh` is ~20 minutes away.

## What the removal actually involves

Guix ships no uninstaller. In order — the `gnu-store.mount` step is the one that
will otherwise bite you:

```bash
sudo systemctl disable --now guix-daemon
sudo rm -f /etc/systemd/system/guix-daemon.service
sudo systemctl daemon-reload

# /gnu/store is a read-only bind mount from gnu-store.mount, so rm -rf /gnu
# fails with "Read-only file system" until the mount is stopped.
sudo systemctl stop gnu-store.mount
sudo rm -f /etc/systemd/system/gnu-store.mount
sudo systemctl daemon-reload
sudo rm -rf /gnu

sudo rm -rf /var/guix /var/log/guix /etc/guix
rm -rf ~/.config/guix ~/.guix-profile ~/.cache/guix
sudo rm -f /etc/profile.d/zzz-guix.sh /etc/profile.d/guix-certs.sh \
            /etc/bash_completion.d/guix /etc/bash_completion.d/guix-daemon
sudo userdel guix-daemon
```

`guix` as a command disappears with `/var/guix/profiles`; there is nothing to
`pacman -R`.

## Verified

- `ls /gnu` → no such file; `command -v guix` → nothing
- `df /` → 5.3 GB used → **5.1 GB**, 231 GB free
- `systemctl --failed` → only the pre-existing qbittorrent DHT transient
  (`getent ahosts bttracker.debian.org`, from 2026-11-07 22:00), nothing new
- `nginx jellyfin cloudflared tailscaled sshd` all `active`
- no `/etc/profile.d`, `fstab`, `environment` or `sudoers` reference left

Nothing removed touched the initramfs, so the TPM2 unlock path is unchanged; a
reboot is not needed for correctness.

## Not done

- Not rebooted to re-prove it, because nothing in the boot path changed.
- `nss-certs` was not replaced with anything — Arch's `ca-certificates` was
  already installed, and nothing had `SSL_CERT_FILE` pointing at `/gnu`.

## Gotcha for next time

`rm -rf /gnu` on a Guix foreign-distro box returns a wall of "Read-only file
system" for every store object. That is not immutable attributes or permissions
— it is `gnu-store.mount`, a systemd unit the installer enables to make the
store read-only. Stop the mount first.
