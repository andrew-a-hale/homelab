# Simplify pass: migration closeout (2026-11-07)

With the migration done (see `migration-2026-11-07.md`) and Tom no longer load
bearing — it runs the petcam only, ~90% uptime is enough — today removed the
machinery that only existed because Tom was fragile or because things had not
finished moving.

## Tom (petcam-only for real now)

- **Purged** jellyfin, nginx, qBittorrent, Proton VPN packages (~600 MB; SD 74% -> 72%).
- **Crontab cleaned**: removed the `@reboot .../andrewahale.com && make down run`
  (it was still resurrecting the old website at every boot) and the dead
  Jellyfin/NFS retry comments. Kept: brownout health logger, the two petcam
  watchdogs and their `@reboot` lines, `wifi-guard`.
- **Removed** `cloudflared-bypass.service` + script — only needed while the
  tunnel lived on Tom.
- Stopped the old website instance that was running from `make run`.
- `dht-daemon` disabled earlier in the day: the D1 mini + DHT12 rig moved to
  Ralph (`/dev/ttyUSB0` is gone from Tom), Ralph's `dht.service` ->
  `/srv/dht/dht.json` is the only sensor now.

## Ralph

- **Proton boot path fixed at the root**: `wg-quick@proton0` was never enabled —
  proton0 came up by luck. Now enabled at boot, and `proton-guard` is wired as a
  timer (`OnBootSec=2min`, `OnUnitActiveSec=5min`) so the tunnel self-heals
  instead of sitting in a failed state. qBittorrent keeps failing closed via
  interface binding to `10.2.0.2`.
- **Dead NFS/RPC stack removed** (rpcbind, rpc-statd, nfs-idmapd/mountd): no
  exports, no mounts, nothing to serve.
- **Host firewall**: ufw, default deny incoming. LAN (`192.168.1.0/24`) and
  tailnet (`100.64.0.0/10`) trusted whole, `41641/udp` for Tailscale direct
  connections, nothing else. No WAN inbound is needed at all — the Cloudflare
  tunnel dials out.
- **qBittorrent login** changed to tom/pancake — that is nginx basic auth on
  `/bt/` (qBit's own WebUI is localhost-only with auth off).

## Router

- DHCP reservation: `192.168.1.26` -> `8C:C6:81:A2:7A:38` (Ralph, wlan0),
  alongside the existing `192.168.1.24` reservation for Tom. Done via the
  D-Link DSL-X1852E UI (`Settings > Network > Reserve IP`).
