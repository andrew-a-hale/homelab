# FP flood — the feed filled with non-cat snapshots (2026-11-03)

**Symptom:** owner: "literally none of the images in the snapshot feed had a
cat." The pool (20) had filled with false positives.

**Causes (three, compounding):**
1. **FP triggers in the room**: rounded black leather couch cushions (cat
   silhouette) and the TV/desk corner fired the 2-class model as "willow".
2. **Flooding**: a firing trigger saved a snapshot + training pair every
   ~5 s, so one trigger owned all 20 pool slots within minutes.
3. **Precision regression**: FPs over the negative set went 2/109 (Nov 1) →
   15/214 (today) as the corpus grew — the recall push traded precision.

**Fixes:**
- **Data first**: the 4 FP frames + 5 fresh captures converted to verified
  negatives (`/review/negative` + `done`, or `/label/reject`). Post-retrain all
  four score **0.001–0.005** (the leather-chair frame was 0.664 even after one
  negative round — it needed several). FPs over 217 negatives: **3** (was 15).
- **`SAVE_COOLDOWN_S=120`** in `petcam-detect.py`: snapshots AND training pairs
  are rate-limited, so no single trigger can flood the feed again.
- **`/delete` now trains**: deleting a snapshot (the owner's FP cleanup habit)
  marks its training pair a verified negative, so deletions teach the next
  retrain. Skipped when a sibling snapshot of the same frame survives (the
  frame does contain a cat).

**Regression probes after the retrain:** unseen stretched willow 0.447 ✓,
curled willow 0.539 ✓ (both correct names).

**Watch item:** if FPs creep back into the feed, the fix loop is now
self-serve — delete them on the page and retrain; raise `MIN_CONF` only if
real cats score comfortably above it.
