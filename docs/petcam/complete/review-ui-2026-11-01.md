# /review UI — verify training labels before a retrain (2026-11-01)

## Task

The user reported heavy pancake/willow misclassification and wanted to retrain.
Investigation showed the training corpus labels carry the errors: since the
2026-10-28 model reset (base COCO yolov8n live), every name comes from the hue
classifier, and its single orange-fraction threshold breaks under real lighting.

## Evidence (186 pairs, 114 boxes, measured 2026-11-01)

- `--checknames`: hue disagrees with hand labels in **9 of 29** named frames.
- Pancake backlit in shadow reads gray → auto-labeled **willow**: a full burst
  (2026-10-31 15:13–15:17, ~14 frames) is pancake per the hand names on
  neighboring frames, but auto-labeled willow at orange 0.05–0.07.
- Warm lamp/golden-hour light reads willow as orange (hand-named willow frames
  at orange 0.35–0.73 — user corrected these at `/label`).
- Hue names **any** non-orange region "willow": a cat-free frame
  (2026-10-29_10-47-18) entered the corpus with 4 boxes on windows/plants/cat
  tree, all class 1.

Retraining on this corpus would bake the confusion in. The labeler and the
training truth are the same component — a human verification step is required.

## What was built (andrewahale.com Go web app)

`/review` on petcam.andrewahale.com (Cloudflare Access), separate from `/label`
which handles near-miss *proposals*; `/review` audits *already-labeled* pairs:

- Frame view with every box drawn (orange = pancake, blue = willow, red dashed
  = flagged) and per-box stats: orange/gray fraction and what the hue rule says.
- Actions: flip box class (pancake/willow), remove box, mark frame negative,
  delete pair, mark reviewed. Keyboard: ← → · D · N · X.
- Suspicious-first order: hue-vs-label disagreements, then multi-box frames,
  then clean, then negatives, then reviewed.
- `training/reviewed.txt` (one stem per line) tracks what the owner verified.

Routes: `GET /review`, `GET /review/list`, `POST /review/{set,delbox,negative,
delete,done}`, `GET /review/img/*`. Hue stats are re-implemented in Go for the
flag/sort only — `petcam-detect.py` stays the naming source of truth.

## Verification

- Go build + `go vet` clean; hue stats cross-checked against the Python
  classifier on real crops (identical values).
- Rendered headless against the full corpus (test build with redirected paths):
  flags, sort order, box overlays, counters and all six POST actions exercised,
  including bad-input and path-traversal rejection.
- Deployed to Tom (`make down run`), `/review` + gallery + main site all 200;
  `/review/list` returns 186 frames in 3.5 s on the Pi.

## Round 2 (same day) — stale cache fix + hue demoted to suggestion

- **Missing link on `/label`**: `/label` and `/live` were served as static
  files without cache headers, so browsers kept stale copies (the review link
  showed on the dynamic gallery but not there). Both now send `no-store`.
- **Hue demoted everywhere it used to decide** (owner: "hue classification is a
  bad idea due to lighting over the day"):
  - `/label` "save · cat" silently wrote class 0 (pancake) whatever the
    suggestion said — exactly the mix-up class being fixed. Saves now require
    `cat=pancake|willow` (server 400 otherwise) and the generic button applies
    the displayed suggestion explicitly.
  - `train-model.sh` trains only on human-verified pairs (`reviewed.txt`,
    `/label` names in the filename, `_neg` rejects). Verified locally: 110 of
    186 current pairs qualify; the 76 unverified hue auto-labels are dropped.
  - `petcam-detect.py` `propose_name()`: name suggestions come from the
    fine-tune's class when the model knows pancake/willow; hue is only the
    base-COCO fallback. `--selftest` passes on Tom.
  - `/review` text: the colour hint sorts the queue and never decides labels.
