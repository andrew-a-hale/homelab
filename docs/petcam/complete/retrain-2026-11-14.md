# Retrain 2026-11-14 — review advances, near-miss floor 0.2, and the metrics

Three changes in one pass, all owner-requested after a labeling session:
reviewing at `/review` now moves on by itself, the near-miss harvest floor went
`0.1 → 0.2` so the `/label` queue stops refilling with noise, and the model was
retrained on the verified corpus (943 pairs) and pushed.

## 1. `/review` — marking reviewed advances

`/review` kept the frame on screen after `✓ reviewed (D)`, so a 300-frame audit
meant a click plus an arrow press per frame. `markDone()` now steps forward
after ticking (unticking stays put). Reviewing is a flow; the filter buttons are
still there for jumping around.

## 2. Near-miss floor `HARVEST_MIN_TOP` 0.1 → 0.2

`harvest()` queues frames scoring `HARVEST_MIN_TOP <= top < MIN_CONF` into
`~/petcam/tolabel/` for hand-labeling (120 s throttle, 25 % sample). The floor
was a hardcoded `0.1`.

From the 14-day `detections.log` window (rolling ~8 k scans):

| top score band | frames |
|---|---|
| 0.05 – 0.10 | 2774 |
| **0.10 – 0.20** | **1371** |
| **0.20 – 0.30** | **679** |
| ≥ 0.30 (auto-save) | 3290 |

Two thirds of everything harvestable sat in 0.1–0.2 — frames where YOLO has
essentially seen nothing. They compete for clicks with the frames that are worth
a box (0.2–0.3), which is why the queue felt infinite. Floor is now a named knob
so the next move is one line. Hard misses (below the floor, no box to propose)
stay the `/live` **Capture** path, as before.

## 3. Model — retrained and deployed

`EPOCHS=100 scripts/train-model.sh` on Jason. 943 verified pairs after the
gate dropped 125 unverified auto-labeled pairs (they still need `/review`).

- Val split (189 frames, Oct 28 – Nov 1, unseen by this model): **P 0.829 /
  R 0.701 / F1 0.760 / mAP50 0.673** — pancake 0.958, willow 0.388 (13 willow
  instances: rough).
- ONNX pushed, previous rotated to `.bak`, `--selftest` ok, detector restarted.

### Metrics: old `.bak` vs this retrain, on days neither model ever saw

Every frame in the corpus is training data for one model or the other, so a
single split flatters whoever trained on it: the same 189-frame val split scores
old **P 0.905 / R 0.877 / mAP50 0.904** (it trained on those days — an upper
bound, not a measurement), and the deployed model scores a useless **mAP50
0.995** on Nov 12–14 for the same reason.

The honest comparison needs a model that never saw the test days. So: a holdout
run (`HOLDOUT_DAYS=2026-11-12,2026-11-13,2026-11-14
VAL_DAYS=2026-11-07,2026-11-10`, never deployed) trained on exactly the same
data minus those three days. Both it and `.bak` are clean on the frozen 168
frames (36 frames with a cat box, 132 cat-free):

| conf 0.3, frozen Nov 12–14 | old `.bak` (Nov 3) | retrain w/ holdout |
|---|---|---|
| **frame accuracy** | 74.4 % | **94.6 %** |
| cat-frame recall | 67 % (24/36) | **86 % (31/36)** |
| empty-frame false alarm | 23 % (31/132) | **3 % (4/132)** |
| box precision / recall | 0.808 / 0.401 | 0.632 / 0.685 |
| **F1** | 0.536 | **0.657** |
| mAP50 (conf .3) | **0.472** | 0.429 |
| mAP50-95 (conf .3) | **0.424** | 0.280 |

Read it as: the new model finds a lot more cat (86 % of cat frames, up from
67 %) and almost stops firing on an empty bed (3 % vs 23 %), at the cost of
box-precision — more of its boxes are misplaced or phantom at low confidence,
which is why mAP50-95 drops. For this app (presence → snapshot → human names it;
`SAVE_COOLDOWN_S` limits the flood) recall + empty-frame quiet beats tight box
geometry. Willow (the curled/sleeping case) is the remaining weak spot: recall
0.265 → 0.481–0.708 depending on conf, vs pancake 0.537 → 0.889.

Note the cat-free frames are themselves model-selected (old near-misses and
deleted snapshots), so 23 % is an upper bound on the old model's false-alarm
rate — but both models were scored on the same biased set, so the comparison
holds.

## 4. Round 2 (same night) — the review backlog was cleared, retrained again

The owner worked the whole `/review` queue: 1062 of 1064 pairs verified (was
773), so the corpus went 943 → 1063 verified pairs (390 with boxes, 673
negatives; 1 unverified pair dropped at training). Same recipe, retrained, and
the gain is large — the newly verified frames were mostly the auto-saved
confident detections that used to be excluded.

Val split (213 frames / 104 boxes, unseen by this model): **P 0.868 / R 0.683 /
F1 0.765 / mAP50 0.731** — pancake 0.946, willow 0.516 (34 willow instances).

Frozen-day twins again (a holdout run that never saw Nov 12–14, scored on the
same 230 frames / 64 boxes — the test-day frames got reviewed too, so this is a
bigger and better-labelled set than round 1's 168/36, which is why the old rows
shift slightly from the table above):

| conf 0.3, frozen Nov 12–14 | old `.bak` | retrain #1 (943 pairs) | retrain #2 (1063 pairs) |
|---|---|---|---|
| frame accuracy | 69.1 % | 93.0 % | **93.9 %** |
| cat-frame recall | 51/64 = 80 % | 84 % | **92 %** |
| empty-frame false alarm | 58/166 = 35 % | 4 % | 5 % |
| box P / R | 0.616 / 0.575 | 0.694 / 0.667 | **0.816 / 0.908** |
| F1 | 0.595 | 0.680 | **0.859** |
| mAP50 | 0.390 | 0.512 | **0.856** |
| mAP50-95 | 0.329 | 0.334 | **0.678** |

Box quality came back with the extra verified frames: F1 0.680 → 0.859 and
mAP50-95 0.334 → 0.678 (the round-3 story of "looser boxes" was a small-corpus
artefact, not a cost of higher recall). Willow, the weak point all along, went
P 0.923 / R 0.900 / mAP50 0.875 on the frozen days.

Live-path gate, run on Ralph through the detector's own `cv2.dnn` decoder (25
random boxed frames + 25 negatives, `harvest`/`log_raw` monkeypatched off):

| | cat frames with a box | cat-free frames firing |
|---|---|---|
| old `.bak` | 24/25 | 1/25 |
| **new** | **25/25** | **0/25** |

`.bak` is now round 1 (the 943-pair model), so a rollback steps back one round,
not to Nov 3.
