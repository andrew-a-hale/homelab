# LAN trust: harden Tom, scope the firewalls, narrow the tailnet

**Status:** §1, §2, §3 done 2026-11-08 — see
`../complete/host-hardening-and-detection-2026-11-08.md` and
`../complete/tailnet-key-only-and-narrow-policy-2026-11-08.md`. Left: the guest
SSID (§6, router UI). §5 (Tom off the tailnet) is deprioritised. Source:
`docs/security/README.md`.

## Goal

No zone is trustworthy by address. A compromised LAN device gains nothing
beyond the one service it can already log in to; a compromised tailnet node
cannot reach root on Ralph.

Done when: `tom` accepts no passwords and no VNC from the LAN, `tom` is no
longer a tailnet node at all, `ralph`'s ufw opens ports per service instead of
per subnet, and `tailscale ssh` to ralph works only from an admin-tagged device
with `check` mode.

## 1. Tom — close the foothold — **DONE 2026-11-08**

Tom is a camera appliance (`docs/ralph/README.md`), not a general host: `rpicam-vid`
| `ffmpeg` into `/dev/shm/petcam` plus `petcam-static` (that is
`python3 -m http.server` on the tailnet IP, not nginx — no website, no tunnel,
no Go on this box). Nothing on it needs a password login or a desktop.

```bash
ssh tom
# sshd: key-only, no root, one user
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/;
             s/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
sudo sshd -T | grep -Ei '^(passwordauth|permitrootlogin)'
```

- **VNC off.** `wayvnc` listens on `0.0.0.0:5900` and there is a `vnc` user.
  It is not used by anything in the petcam path — disable
  `wayvnc.service` + `wayvnc-control.service` (RPi OS ships them enabled, and
  underwrites `/usr/sbin/wayvnc-run.sh` as the wrapper). If a console is ever
  needed, bind it to `tailscale0` instead of `0.0.0.0`.
- **rpcbind off** (`sudo systemctl disable --now rpcbind rpcbind.socket`) —
  nothing here does NFS as a server.
- **Firewall** (ufw is not installed on Tom at all):

  ```bash
  sudo apt install -y ufw
  sudo ufw default deny incoming
  sudo ufw default allow outgoing
  sudo ufw allow in on tailscale0   # petcam-static :8081 is tailnet-only already
  sudo ufw enable
  ```

  Note this also stops Ralph's detector from reaching `:8081` if the tailnet
  interface name differs — verify with
  `ssh ralph 'curl -sS -m 5 -o /dev/null -w "%{http_code}\n" http://100.77.132.110:8081/frames/latest.jpg'`
  expecting `200` after enabling.
- **sudo:** `tom` has `(ALL : ALL) ALL` with no password. Nothing on Tom uses
  sudo except `scripts/petcam.sh`'s reboot path. Scope it to that, or accept
  the risk knowingly with a comment in `/etc/sudoers.d/`. (`ralph`'s NOPASSWD
  is a separate item — the units genuinely need it there, so scope it per
  unit rather than remove it.)

## 2. Ralph — stop trusting the LAN as a zone — **DONE 2026-11-08**

Current rules (`ufw status numbered`) trust all of `192.168.1.0/24` and all of
`100.64.0.0/10` on every port.

```bash
ssh ralph
sudo ufw delete allow from 192.168.1.0/24
sudo ufw allow from 192.168.1.0/24 to any port 80 proto tcp   # nginx: /bt/ + /jf/ + site
sudo ufw allow from 192.168.1.0/24 to any port 8096 proto tcp # Jellyfin direct for TV/mobile
# keep tailnet broad enough for ssh/jellyfin, or narrow to those two ports too
```

Verify the TVs and phones still play before closing the ticket — `/jf/` via
nginx needs `80`, the Jellyfin apps may hit `8096` directly.

## 3. Tailnet — key-only SSH, narrow policy — **DONE 2026-11-08**

`tailscale set --ssh=false` on ralph and tom (tailnet SSH is now sshd + keys:
`Authenticated … using "publickey"`, and `PubkeyAuthentication=no` is refused),
then `docs/vpn/tailnet-acl.hujson ` pasted: `ralph:22,80,8096`, `tom:22,8081`,
`192.168.1.0/24`, **no `ssh` block**. Enforced — ralph → jason`:22` is blocked,
while ralph → tom`:8081` and jason → ralph`:8096` still answer.

Gotcha recorded for next time: `dst` needs an **address**, not a machine name
(`"ralph:22"` → `invalid address`), and `src` accepts only
tags/groups/autogroups/users. Tags are deliberately deferred (they force a
re-auth, which strands a headless node until the login URL is opened) — do them
later with a pre-created auth key. Never `action: "check"`: a 12-hourly browser
re-auth breaks the 08:00 health check. Decision record:
`../complete/tailnet-key-only-and-narrow-policy-2026-11-08.md`.

## 5. Take Tom off the tailnet — **DEPRIORITISED 2026-11-08**

Both reasons evaporated: Tom no longer answers tailnet SSH by identity (§3), and
its sshd is key-only with a firewall. Removing the node buys one less tailnet
identity, in exchange for rebinding `petcam-static` to `192.168.1.24`, a LAN-only
firewall rule, and three edits on Ralph.

Keep as an option if the tailnet should shrink to a trusted few. If picked up:
rebind first, then repoint Ralph's nginx `/hls/`, `petcam-detect.py`'s `STILL` and
`scripts/homelab-health.sh`'s `TOM_HOST`, then `tailscale logout` on Tom — moving
the `192.168.1.0/24` route to Ralph first, with its approval in the console,
before the phone needs it.

## 6. Guest SSID for the things that will never be trustworthy — **BLOCKED: router UI**

20 min; the router admin password is in `pass 192.168.1.1-admin`.

Ralph and Tom stay on the main SSID. The bulb (`TODO.md` → Shelly), the TV,
